# 1. What is service mesh

<img width="845" height="380" alt="image" src="https://github.com/user-attachments/assets/a54c7f36-7c02-4ab2-9f97-13f9f8d19d1d" />


- Service mesh helps with the traffic management of kubernetes cluster , **(specially East-West)**
- Suppose assume a Ecommerce application with microservices - Login, catalogue, payment, Notification
    - Login microservice talks to --> catalogue microservice --> payment --> Notification ( user get a notification about the order )
- Suppose user need to access the above ecommerce app, then we need to create a ingress. So somehow user present in the outside of the cluster need to access the application which is inside the cluster.
- So traffic coming from outside of the cluster is called **(North-south)** traffic and the other one internal service to service is called **East-West** Traffic.
- So traffic coming inside(which is ingress) and traffic going outside(which is egress) is called as **East-West** traffic.
- **Istio** definition tells it will help for service to service communication, however already service to service communication is enabled unless you enforced network policies.

# 2. Why service mesh


- As said above it is used to secure service to service communication and also it has some add on capabilities on this. for Eg: **Mutual TLS(mtls)**
- **Advanced deplyment capabilities** , we can implement deployment strategies like Canary, A-B, Blue green deployment in very Easy way, which means little less difficulties
- Also it has good observability, we need to install a tool called kiali. and we can use this to see how our service to service communication is behaving.

  ## What is mTLS
- Login mic will have certificate and Catalogue mic will have certificate which is generated by the certification authority of Istio.
- So when login mic wants to communicate with catalogue mic, will display their certificates to each other and only when both of them trust each other, communication will get established
- Its slightly different then the traditional TLS approach and its a advance level of security

 ## How Traditional TLS works
 - Usually here client will display their certificate to the server and if server acknowledges then a trust is established and communication established.

# 3. How Istio works

- what istio does is , in all pods of the kubernetes cluster. ofcourse the namespaces which istio access to .
- within each and every pod it will add a new container, which will sit next to the actual pod and this new container is called as sidecar container.
- what is inside side care container --> It has Envoy proxy application, which will handle traffic management of the kubernetes pod.
